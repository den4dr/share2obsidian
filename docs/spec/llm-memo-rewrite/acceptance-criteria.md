## REQ-001〜003・REQ-406: 本文のLLMリライト 🔵

**信頼性**: 🔵 *ヒアリングQ2・Q7・Q24より*

### Given（前提条件）
- SettingsScreenでLLM APIエンドポイントURL・APIキー・モデル名が設定済み
- テンプレートに本文用LLMプロンプトが設定済み
- EditScreenが表示されている（共有/取得直後の元コンテンツ ProcessedContent が保持されている）

### When（実行条件）
- ユーザーが「メモを更改」ボタンを押す

### Then（期待結果）
- ローディング表示が開始される
- LLM APIへ共有/取得直後の元コンテンツ（ProcessedContent。EditScreen上の編集済みbodyではない）とテンプレートのプロンプトが送信される
- 応答テキストで本文フィールドが即時上書きされる

### テストケース

#### 正常系

- [x] **TC-001-01**: 本文リライトが成功し本文が上書きされる 🔵
  - **入力**: ProcessedContent="今日は天気が良かった。散歩に行った。", プロンプト="要約して"
  - **期待結果**: LLM応答テキストで本文フィールドが上書きされる（EditScreen上でユーザーが編集済みの内容ではなく、元コンテンツが送信されたことを確認する）
  - **信頼性**: 🔵 *ヒアリングQ2・Q7・Q24より*

- [x] **TC-001-02**: リライト中はローディング表示され、完了後に解除される 🔵
  - **入力**: 上記と同条件
  - **期待結果**: リクエスト開始時にローディング表示、応答受信後にローディングが消える
  - **信頼性**: 🔵 *ヒアリングQ10より*

- [x] **TC-001-03**: EditScreen上で本文を編集した後でも、LLMへは編集前の元コンテンツが送信される 🔵
  - **入力**: ProcessedContent="元のテキスト", EditScreen上で本文を"編集後のテキスト"に変更済み
  - **期待結果**: LLMリクエストの入力は"元のテキスト"（ProcessedContent）であり、"編集後のテキスト"ではない
  - **信頼性**: 🔵 *ヒアリングQ24（入力ソースの確定）より*

#### 異常系

- [x] **TC-001-E01**: ネットワーク未接続時にエラーがToast表示される 🔵
  - **入力**: ネットワーク切断状態で「メモを更改」を押下
  - **期待結果**: 日本語Toastエラーメッセージが表示され、本文は変更されない
  - **信頼性**: 🔵 *ヒアリングQ6・EDGE-001より*

- [x] **TC-001-E02**: APIキー不正時にエラーがToast表示される 🔵
  - **入力**: 不正なAPIキーを設定した状態で「メモを更改」を押下
  - **期待結果**: 日本語Toastエラーメッセージが表示され、本文は変更されない
  - **信頼性**: 🔵 *ヒアリングQ6・EDGE-002より*

- [x] **TC-001-E03**: 30秒タイムアウト時にリクエストがキャンセルされエラー表示される 🔵
  - **入力**: LLM APIが30秒以上応答しない状態
  - **期待結果**: 30秒経過時点でリクエストがキャンセルされ、日本語Toastエラーメッセージが表示される
  - **信頼性**: 🔵 *ヒアリングQ10・EDGE-003より*

- [x] **TC-001-E04**: LLMが空応答を返した場合、本文が上書きされない 🟡
  - **入力**: LLM APIが空文字列を返す
  - **期待結果**: 本文フィールドは変更されず、エラーメッセージが表示される
  - **信頼性**: 🟡 *既存エラー処理方針からの推測。EDGE-004参照*
  - **備考**: 空応答時の扱いは直接確認していないため、設計フェーズで再確認が必要

#### 境界値

- [x] **TC-001-B01**: 元コンテンツ（ProcessedContent）が空文字の状態で「メモを更改」を押下した場合、ボタンは非活性化されず空のままLLMへ送信される 🔵
  - **入力**: ProcessedContent=""
  - **期待結果**: ボタンは活性状態のまま押下可能で、空文字のままLLM APIへ送信される（応答内容はプロンプト次第）
  - **信頼性**: 🔵 *ヒアリングQ21〜Q24・EDGE-101より*

- [x] **TC-001-B02**: テンプレートに本文用LLMプロンプトが未設定の場合、「メモを更改」ボタンは表示されるが非活性化される 🔵
  - **入力**: テンプレートのbodyLlmPromptが未設定
  - **期待結果**: 「メモを更改」ボタンがグレーアウトされ押下できない
  - **信頼性**: 🔵 *ヒアリングQ20・REQ-102より*

## REQ-004・REQ-401: LLM設定・APIキー暗号化保存 🔵

**信頼性**: 🔵 *ヒアリングQ1・Q4・Q8より*

### Given（前提条件）
- SettingsScreenを開いている

### When（実行条件）
- APIエンドポイントURL・APIキー・モデル名を入力して保存する

### Then（期待結果）
- 入力値がDataStore/暗号化ストレージへ保存される
- APIキーは暗号化ストレージに保存され、平文DataStoreには保存されない

### テストケース

#### 正常系

- [x] **TC-004-01**: LLM設定項目（URL/キー/モデル名）が保存される 🔵
  - **入力**: URL="https://api.example.com/v1/chat/completions", キー="sk-xxxx", モデル名="gpt-4o"
  - **期待結果**: 設定値が永続化され、アプリ再起動後も保持される
  - **信頼性**: 🔵 *ヒアリングQ8より*

- [x] **TC-004-02**: APIキーが暗号化ストレージに保存され、平文DataStoreファイルに含まれない 🔵
  - **入力**: APIキー="sk-xxxx"を保存
  - **期待結果**: DataStore Preferencesファイルの内容にAPIキーの平文が含まれない
  - **信頼性**: 🔵 *ヒアリングQ4・REQ-401より*

#### 異常系

- [x] **TC-004-E01**: 接続情報の事前検証は行われない（保存時にAPI疎通確認をしない） 🔵
  - **入力**: 存在しないURLを保存
  - **期待結果**: 保存時にエラーは発生せず、そのまま保存される（エラーは実際のリライト実行時に判明）
  - **信頼性**: 🔵 *ヒアリングQ12・REQ-404より*

## REQ-103・REQ-301・REQ-302・REQ-406: タグ提案（Should Have） 🔵

**信頼性**: 🔵 *ヒアリングQ13・Q17・Q18・Q24より*

### Given（前提条件）
- EditScreenが表示されている（共有/取得直後の元コンテンツ ProcessedContent が保持されている）
- LLM API設定が完了している

### When（実行条件）
- 「タグを提案」ボタンを押す

### Then（期待結果）
- 共有/取得直後の元コンテンツ（ProcessedContent、本文リライトと同一の入力ソース）を入力としてLLMがタグ候補を生成する
- 生成されたタグが既存のタグ入力欄に追加される（既存タグは保持）

### テストケース

#### 正常系

- [x] **TC-301-01**: タグ候補が提案され既存タグに追加される 🔵
  - **入力**: ProcessedContent="旅行の計画について", 既存タグ="private"
  - **期待結果**: タグ入力欄が "private, 旅行, 計画" のように既存タグ+提案タグになる
  - **信頼性**: 🔵 *ヒアリングQ17より*

- [x] **TC-301-02**: 元コンテンツが空文字であっても「タグを提案」ボタンは非活性化されない 🔵
  - **入力**: ProcessedContent=""
  - **期待結果**: ボタンは活性状態のまま押下可能
  - **信頼性**: 🔵 *ヒアリングQ22〜Q24・EDGE-101より*

#### 異常系

- [x] **TC-301-E01**: タグ提案中にLLM呼び出しが失敗した場合、既存タグは変更されない 🟡
  - **入力**: ネットワーク未接続状態で「タグを提案」を押下
  - **期待結果**: 日本語Toastエラーメッセージが表示され、タグ入力欄は変更されない
  - **信頼性**: 🟡 *本文リライトのエラー処理方針（NFR-201）からの類推*

## REQ-104・REQ-303・REQ-304: カスタムフィールドのLLM生成（Could Have） 🟡

**信頼性**: 🟡 *ヒアリングQ13・Q15から妥当な推測（生成タイミングは未確認）*

### Given（前提条件）
- テンプレート編集画面でカスタムフィールドを追加している

### When（実行条件）
- 値取得方法（FieldValueSource）として「LLM」を選択する

### Then（期待結果）
- そのフィールド用のプロンプト入力欄が表示される
- 保存後、フィールドの値取得方法としてLLMが記録される

### テストケース

#### 正常系

- [x] **TC-104-01**: FieldValueSourceに「LLM」を選択するとプロンプト入力欄が表示される 🔵
  - **入力**: FieldAddDialogで値取得方法="LLM"を選択
  - **期待結果**: プロンプト入力用のテキストフィールドが表示される
  - **信頼性**: 🔵 *ヒアリングQ15より*

- [x] **TC-104-02**: LLM生成のカスタムフィールド値がテンプレート適用時に生成される 🟡
  - **入力**: FieldValueSource="LLM", プロンプト="URLからカテゴリを推測して"
  - **期待結果**: テンプレート適用時（またはEditScreen操作時）にLLMで値が生成されCustomFieldStateに反映される
  - **信頼性**: 🟡 *生成タイミングは未確認。REQ-304参照*
  - **備考**: 設計フェーズで生成タイミングを確定する必要がある
