## 実装詳細

### 1. LlmRewriteResult sealed class 🔵

**信頼性**: 🔵 *interfaces.kt「LLM 呼び出し結果（新規）」・EDGE-001〜004より*

`LlmRewriteResult` を sealed class として定義する。

- `Success(val text: String)`: 呼び出し成功時、書き換え/生成されたテキストを保持する（REQ-003）
- `Failure` は sealed class とし、`abstract val messageResId: Int` を持つ
  - `NetworkError(override val messageResId: Int)`: ネットワーク未接続・接続エラー（EDGE-001）
  - `AuthError(override val messageResId: Int)`: APIキー不正・認証エラー（HTTP 401/403）（EDGE-002）
  - `Timeout(override val messageResId: Int)`: 30秒タイムアウト（EDGE-003, NFR-001）
  - `EmptyOrInvalidResponse(override val messageResId: Int)`: 空応答・パース不能なレスポンス 🟡（EDGE-004）
  - `Unknown(override val messageResId: Int)`: 上記以外の予期しないエラー 🟡（一般的なエラーハンドリング方針からの推測）

**実装ファイル**: `app/src/main/java/com/den4dr/share2Obsidian/data/llm/LlmRewriteResult.kt`

## 単体テスト要件

### テストケース1: ChatCompletionRequestDto のエンコード結果がAPI仕様と一致する 🔵

**信頼性**: 🔵 *api-endpoints.md「リクエスト仕様」JSON例より*

**Given**: `model = "gpt-4o"`, `messages = [ChatMessageDto("system", "プロンプト"), ChatMessageDto("user", "元コンテンツ")]` を持つ `ChatCompletionRequestDto`
**When**: `Json.encodeToString()` でエンコードする
**Then**: api-endpoints.md記載の `{"model":"gpt-4o","messages":[{"role":"system","content":"プロンプト"},{"role":"user","content":"元コンテンツ"}]}` 形式のJSONと一致する

### テストケース2: サンプルレスポンスJSONをデコードできる 🔵

**信頼性**: 🔵 *api-endpoints.md「レスポンス仕様」JSON例より*

**Given**: `{"choices":[{"message":{"role":"assistant","content":"書き換え結果"}}]}` というJSON文字列
**When**: `Json.decodeFromString<ChatCompletionResponseDto>()` でデコードする
**Then**: `choices[0].message.content` が `"書き換え結果"` として取得できる

### テストケース3: choicesが空配列のレスポンスをデコードした場合の挙動確認 🟡

**信頼性**: 🟡 *EDGE-004関連（空応答時の扱いは直接確認していない）*

**Given**: `{"choices":[]}` というJSON文字列
**When**: `Json.decodeFromString<ChatCompletionResponseDto>()` でデコードする
**Then**: 例外を投げずにデコードでき、`choices` が空リストとして取得できる（空応答時のFailureへのマッピングはTASK-0060で扱う）
